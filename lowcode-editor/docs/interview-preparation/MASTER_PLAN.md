## 1. 用户背景与最终目标

用户此前从事 QA，近期在学习前端开发，计划约一个月后参加前端开发工程师面试。目标岗位在招聘信息中通常要求 3 年以上前端经验。

执行原则：

1. 不虚构工作年限或项目经历。
2. 用扎实的前端知识、可运行的项目、工程化能力、质量意识和可信的表达，缩小与目标岗位要求的差距。
3. 将 QA 背景转化为优势，包括测试思维、边界分析、质量保障、问题定位和协作经验。
4. 面试训练和项目升级并行推进；知识点尽可能落到项目实践，项目功能也必须能转化为面试回答。
5. AI 功能必须融入低代码编辑器核心流程，不以普通聊天框冒充项目亮点。

### 最终成功标准

30 天结束时，至少应达到以下状态：

- 完成一套覆盖中级前端核心能力的 30 天学习、练习和复盘记录。
- 建立带来源、日期、频率、答案与追问链的国内前端面试题库。
- 能完成常见 JavaScript/TypeScript 手写题和基础算法题，并解释复杂度、边界与取舍。
- 当前低代码编辑器能够稳定运行，具备清晰架构、核心编辑能力、测试与工程化说明。
- 至少完成 1 个融入编辑器工作流、可演示、可解释的 AI 主功能。
- 形成可用于简历的项目描述、3 分钟与 10 分钟项目介绍，以及项目深挖问答。
- 至少完成 3 轮综合模拟面试，并针对弱项闭环复练。
- 用户能够诚实、连贯地说明 QA 转前端的动机、准备过程与独特优势。

## 3. 工作范围

### A. 面试训练

- HTML、CSS、JavaScript、TypeScript。
- React 及项目实际涉及的框架原理。
- 浏览器、HTTP/HTTPS、网络、安全、性能与可访问性。
- 工程化、构建工具、模块化、包管理、规范、测试与 CI。
- 状态管理、组件设计、前端架构和场景设计题。
- 手写题、基础算法、调试与故障定位。
- 项目介绍、项目深挖、行为面试、QA 转前端叙事。

### B. 国内面试信息调研

- 按用户要求，优先使用 `Panniantong/Agent-Reach`。
- 安装说明源：`https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md`。
- 调研目标仅限国内 3～5 年前端岗位、React/TypeScript/中级前端、低代码前端、AI 前端应用和工程化相关真题、面经与面试技巧；排除后端、测试开发和无前端关联的泛 AI 面经。
- 信息源仅使用小红书、B站、知乎、脉脉、掘金、牛客；其他平台不得进入正式题库和知识总结，除非用户后续明确扩展范围。
- 每条材料尽可能记录原始链接、平台、发布日期/抓取日期、岗位层级、题目原文摘要、可信度及是否交叉验证。
- 个人面经只代表个案，不得包装为通用事实；过期资料必须标注。

### C. 项目升级

必须从以下方向深入分析并落地：

- 项目作用、用户、业务场景和价值主张。
- Schema/组件协议、渲染流程、状态模型和实现方式。
- 拖拽、选中、属性编辑、撤销重做、快捷键、导入导出、预览等核心能力。
- 可扩展组件体系、插件机制、数据源/事件绑定和代码生成。
- 性能、安全、错误处理、可访问性、测试、CI 与文档。
- 项目难点、技术亮点、取舍、失败方案和量化结果。

### D. AI 差异化能力

优先主线：

`自然语言需求 -> 结构化页面 Schema -> Schema 校验/修复 -> 变更预览 -> 用户确认 -> 写入编辑器 -> 可撤销 -> 继续局部修改`

应体现：结构化输出、流式状态、Prompt/上下文设计、校验、错误恢复、权限与安全、成本/延迟、可观测性和人机确认机制。

## 4. 非目标与边界

- 不帮助用户伪造 3 年前端工作经历。
- 不无依据地承诺一个月达到真实 3 年从业者的全部能力。
- 不为追求“功能多”而堆砌不可运行或无法解释的功能。
- 未获得授权时，不推送代码、不发布线上服务、不创建外部账号、不购买 API 或产生费用。
- 不记录密码、Token、Cookie 等秘密；只记录配置项名称和安全的验证结果。
- 不覆盖用户已有的未提交修改；遇到重叠修改必须先说明。

## 7. 每日标准作业流程

每个训练日按以下顺序执行：

1. **读取状态**：阅读本文件的元信息、进度、阻塞、最近 Changelog；再阅读最近一份日报和相关阶段报告。
2. **确认输入**：检查用户上一日答题、代码、反馈、新要求和可投入时间。
3. **提供训练包**：包括目标、知识点、真题、手写题、项目任务、口述题和验收标准。
4. **执行项目工作**：改代码前检查 Git 状态；先理解已有实现；保留用户修改；进行与风险匹配的验证。
5. **批改与追问**：按准确性、原理深度、工程意识、表达结构、边界思考分别反馈，不只给标准答案。
6. **记录证据**：保存题目来源、用户答案、测试命令、结果、截图/报告路径和未解决项。
7. **更新计划**：更新进度、当前任务、下一步、风险、需求、决策和 Changelog。

### 每日训练包最低结构

- 今日目标（不超过 3 个核心目标）
- 预计用时与必做/选做划分
- 知识讲解与高频追问
- 2～5 道有来源的面试题
- 1～3 道手写/场景题
- 1 个与当前项目相关的实践任务
- 口述题与评分标准
- 当日验收条件
- 次日复习入口

如果尚未获知用户每日可投入时长，默认设计为 2～4 小时，并把内容分成 90～120 分钟必做与可选加练。

## 10. 项目改造优先级与验收规则

### 优先级

- `P0`：项目无法运行、核心流程断裂、数据丢失、高风险安全/类型问题。
- `P1`：能显著体现中级前端工程能力的架构、功能、测试和性能事项。
- `P2`：增强差异化、扩展性、演示效果或面试深度的事项。

### 单项任务完成定义（Definition of Done）

项目任务只有同时满足下列条件才可标为完成：

- 需求和验收标准明确。
- 实现或文档已落地，且没有覆盖无关用户修改。
- 类型检查、构建、Lint 和相关测试按风险执行并记录结果。
- 关键交互完成手工验证；必要时保存截图或复现步骤。
- 已补充错误、空状态、边界与可访问性考虑。

- 本文件的进度、产物链接与 Changelog 已更新。

## 11. AI 功能阶段门

AI 主功能按以下阶段推进：

1. `AI-0 需求`：明确用户场景、输入输出、非目标和成功指标。
2. `AI-1 协议`：定义 Schema、工具/动作协议、校验和版本策略。
3. `AI-2 原型`：用固定样例打通自然语言到 Schema，不直接写入正式画布。
4. `AI-3 安全写入`：加入 Diff、预览、确认、权限限制、撤销和错误恢复。
5. `AI-4 评测`：正常/边界/失败/恶意输入、延迟、成功率和成本记录。
6. `AI-5 面试交付`：演示脚本、架构说明、技术取舍和追问答案。

禁止跳过 `AI-1` 直接让模型生成任意可执行代码；默认优先生成受约束的声明式 Schema。
